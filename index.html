Spring Data

¿Qué es?

Una parte de Spring que escribe por vos el código para guardar y buscar datos en una base.

VOSServiceTu lógica: le pide datos al repositorio.
→
VOSRepositoryUna interfaz de una línea.

public interface ActorRepository extends JpaRepository<Actor, Integer> { }

Esto es todo lo que escribís. La clase que hace el trabajo la genera Spring al arrancar.

El contenedor

¿Quién crea los objetos?

SIN SPRINGLos creás vos, en orden

EntityManager em = emf.createEntityManager();
ActorRepository repo = new JpaActorRepository(em);
ActorService service = new ActorService(repo);
ActorController ctrl = new ActorController(service);
// ...y lo mismo para las películas

Hay que crearlos en el orden justo. Si cambia un constructor, hay que tocar todo esto.

CON SPRINGLos pedís en el constructor

@Service
public class ActorService {

    public ActorService(ActorRepository repo) {
        ...
    }
}

Al arrancar, Spring crea cada objeto y le pasa lo que pide. A esos objetos se los llama beans.

Nadie escribe new: los crea y los conecta el contenedor de Spring.

¿Por qué actorRepository se crea antes que actorService?

Porque actorService lo pide en su constructor. Spring crea primero lo que otro necesita. Y cada uno se crea una sola vez (singleton).
